## ก่อนเริ่ม

1. เปิด [สแกนและเลือกอุปกรณ์](/features/wifi-scan) หากฟีเจอร์ระบุ `Selected AP` หรือ `Selected STA`
2. เตรียม Router และอุปกรณ์ทดสอบที่คุณควบคุมได้
3. ตรวจวิธีหยุดที่ [วิธีหยุดฟีเจอร์](/getting-started/controls#หยุดฟีเจอร์ที่กำลังทำงาน)
4. ตรวจพื้นที่ว่างใน [FILES → File Explorer](/features/files#file-explorer) หากต้องบันทึกไฟล์

## Deauth

ใช้สำหรับทดสอบว่าอุปกรณ์หลุดจาก Wi‑Fi แล้วเชื่อมต่อกลับได้หรือไม่

| ตัวเลือก | ใช้ทำอะไร |
| --- | --- |
| `All` | ตัดการเชื่อมต่อทุก AP ที่ตรวจพบ |
| `Mass` | ตัดการเชื่อมต่อหลาย AP ต่อเนื่อง |
| `Selected AP` | ตัดการเชื่อมต่อเฉพาะ AP ที่เลือกไว้ |
| `Selected STA` | ตัดการเชื่อมต่อเฉพาะอุปกรณ์ Client ที่เลือกไว้ |

ผลที่เกิดขึ้น: อุปกรณ์ทดสอบอาจหลุดจาก Wi‑Fi และพยายามเชื่อมต่อใหม่

## Whitelist

ใช้สำหรับยกเว้นอุปกรณ์ที่ไม่ต้องการให้ถูกตัดการเชื่อมต่อระหว่างทดสอบ

1. [สแกนและเลือก STA](/features/wifi-scan#sta--โทรศัพท์หรือ-client)
2. เลือก `Whitelist → Selected STA`
3. ตรวจว่าอุปกรณ์ที่เลือกอยู่ในรายการยกเว้นก่อนเริ่มทดสอบ

## Beacon Spam

ใช้จำลองชื่อเครือข่าย Wi‑Fi จำนวนมาก เพื่อทดสอบการแสดงรายการ Wi‑Fi ของอุปกรณ์

เส้นทางเมนู: `WIFI → ATTACK → Beacon Spam`

| ตัวเลือก | ใช้ทำอะไร |
| --- | --- |
| `All` | ใช้ชื่อจาก AP ที่เคยสแกนพบ |
| `Selected AP` | ใช้ชื่อจาก AP ที่เลือกไว้ |
| `Random` | สร้างชื่อแบบสุ่ม |
| `Prefix` | สร้างชื่อโดยเติมข้อความนำหน้า เช่น `TEST_001` |

ผลที่เกิดขึ้น: รายการ Wi‑Fi ของอุปกรณ์ทดสอบอาจแสดงชื่อเครือข่ายจำนวนมาก

## Handshake

ใช้บันทึกข้อมูลการเชื่อมต่อ Wi‑Fi เป็นไฟล์ `.pcap` เพื่อวิเคราะห์ความปลอดภัยของเครือข่ายที่ได้รับอนุญาต

| ตัวเลือก | ใช้ทำอะไร |
| --- | --- |
| `Auto Active` | ตัดการเชื่อมต่อและจับ Handshake โดยอัตโนมัติ |
| `Selected AP` | จับ Handshake เฉพาะ AP ที่เลือกไว้ |

ก่อนเริ่ม ให้ตรวจพื้นที่ว่างและห้ามเผยแพร่ไฟล์จากเครือข่ายที่ไม่ใช่ของคุณ

## Evil Portal

ใช้สร้าง Access Point และหน้าเว็บจำลองใน Lab ที่คุณควบคุม เพื่อทดสอบการแยกแยะหน้าเว็บปลอม

| ตัวเลือก | ใช้ทำอะไร |
| --- | --- |
| `Default` | ใช้ Template ที่มีในเครื่อง |
| `Selected AP` | ใช้ชื่อ AP ที่เลือกไว้ร่วมกับ Template ที่เกี่ยวข้อง |

ห้ามเก็บรหัสผ่านหรือข้อมูลส่วนตัวของผู้อื่น ใช้ข้อมูลทดสอบเท่านั้น

## Auth Overload

ใช้ส่งคำขอยืนยันตัวตนจำนวนมากไปยัง AP เพื่อทดสอบการจัดการคำขอของ Router

| ตัวเลือก | ใช้ทำอะไร |
| --- | --- |
| `All` | ส่งคำขอไปยัง AP ที่ตรวจพบทั้งหมด |
| `Selected AP` | ส่งคำขอไปยัง AP ที่เลือกไว้ |

ผลที่อาจเกิดขึ้น: Router อาจช้าลงหรืออุปกรณ์ใหม่อาจเชื่อมต่อไม่ได้ชั่วคราว

## Assoc Overload

ใช้ส่งคำขอเชื่อมต่อจำนวนมากไปยัง AP เพื่อทดสอบการรองรับการเชื่อมต่อพร้อมกัน

| ตัวเลือก | ใช้ทำอะไร |
| --- | --- |
| `All` | ส่งคำขอไปยัง AP ที่ตรวจพบทั้งหมด |
| `Selected AP` | ส่งคำขอไปยัง AP ที่เลือกไว้ |

ผลที่อาจเกิดขึ้น: Router อาจปฏิเสธการเชื่อมต่อใหม่หรืออุปกรณ์เดิมอาจหลุดชั่วคราว

## Force CSA

ใช้ทดสอบว่าอุปกรณ์ตอบสนองต่อคำสั่งเปลี่ยน Channel อย่างไร

| ตัวเลือก | ใช้ทำอะไร |
| --- | --- |
| `All` | ส่งคำสั่งไปยังอุปกรณ์ที่ตรวจพบทั้งหมด |
| `Selected AP` | ส่งคำสั่งไปยัง AP ที่เลือกไว้ |
| `Selected STA` | ส่งคำสั่งไปยัง Client ที่เลือกไว้ |

ผลที่อาจเกิดขึ้น: อุปกรณ์อาจหลุดชั่วคราวและต้องค้นหา Channel ใหม่

## DNS Repeater

ใช้เป็น DNS Server ชั่วคราวเพื่อทดสอบการส่งต่อคำขอ DNS ในเครือข่ายที่คุณควบคุม

เริ่มเมนูนี้โดยตรง แล้วตรวจการตอบสนองของอุปกรณ์ทดสอบหลังเริ่มทำงาน

## หยุดการทดสอบและตรวจผล

1. ใช้ [วิธีหยุดฟีเจอร์](/getting-started/controls#หยุดฟีเจอร์ที่กำลังทำงาน)
2. ตรวจว่าอุปกรณ์ทดสอบกลับมาเชื่อมต่อ Wi‑Fi ได้ตามปกติ
3. หาก Router หรืออุปกรณ์ยังผิดปกติ ให้รีสตาร์ทอุปกรณ์นั้น

หากหน้าจอไม่ตอบสนอง ให้ดู [ฟีเจอร์ไม่หยุดหรือหน้าจอค้าง](/help/troubleshooting#ฟีเจอร์ไม่หยุดหรือหน้าจอค้าง)
